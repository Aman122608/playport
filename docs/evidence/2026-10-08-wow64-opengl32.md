# Evidence: an i386 child's opengl32 attaches with the GL-absent table

**Date:** 2026-10-08. **Phone:** iPhone18,4, iOS 27.0, Wi-Fi, dev build, driven with `pp ui`;
the session was unattended. **Linear:** PLA-107 (the fix), PLA-108 (Super Meat Boy),
PLA-12. Run directories are under `$PLAYPORT_BUILD/ui-runs/`; the screenshots stay there.

## The bug

`patches/madeira-unix` 0068 gives an i386 child's unix libraries their WoW64 tables, and any
library without one the stub table, whose every code returns `STATUS_NOT_SUPPORTED`. On iOS
`opengl32`'s own table is the GL-absent one (`ios_gl_stub_unix_call_table`): codes 0 to 2
(`process_attach`, `thread_attach`, `process_detach`) succeed and every GL and WGL call fails.
0068 swapped it for the stub table, so i386 `opengl32`'s `DllMain` failed on
`UNIX_CALL( process_attach )`, and with it every i386 process that loads opengl32. Super Meat
Boy (Epic `Buffalo`) reaches it through `d3dx9_43` → `d3dcompiler_43` → `wined3d` →
`opengl32` ([2026-10-08-super-meat-boy.md](2026-10-08-super-meat-boy.md)).

Before, on `Playport-26.5-44b6e3dc.ipa` (runs `agent-notes/super-meat-boy/play1`, `play2`):

```
[unixlib] module 0x70b2390000 (opengl32.dll) WoW64 -> 0x163dba638 (stub table)
002c:err:opengl:DllMain Failed to load unixlib, status 0xc00000bb
002c:err:module:loader_init "opengl32.dll" failed to initialize, aborting
```

and the title exited `0xc0000142` 0.19 s after it started.

## The fix

`patches/madeira-unix/0099-ntdll-let-an-i386-child-s-opengl32-attach-with-the-G.patch`
(`build/ntdll-unix/virtual_ios.c`, `load_builtin_unixlib`): the WoW64 selection keeps
`ios_gl_stub_unix_call_table` for a WoW64 caller. Its entries read no parameter block, so the
same table serves 32-bit callers. An i386 child now gets what a 64-bit process gets: opengl32
loads, and every GL call fails with `STATUS_NOT_SUPPORTED`. A title that draws with OpenGL
still cannot run (no OpenGL driver on iOS). A new patch rather than an amended 0068: 0068 has
its own evidence (Portal 2), and this change has a separate cause and its own runs.

The other i386 modules that get the stub table (the PE `DllMain` read in the `wine` tree):
`avicap32`, `netapi32`, `qcap`, `winegstreamer` ignore the unix result; `dnsapi`, `winscard`,
`wpcap`, `winedmo`, `odbc32`, `winspool.drv` log or carry on; `opencl` and `wineps.drv` fail
only if `__wine_init_unix_call` itself fails, which the stub path never does. `ctapi32` fails
its attach on a failed unix call, but it gets the same stub table on the 64-bit side, so this
is not 0068's mechanism (and no title found needs a card-terminal API). `msv1_0`'s
`DllMain` only needs `__wine_init_unix_call`. The `.sys` drivers run in 64-bit processes. So
opengl32 is the only i386 module whose load fails through the WoW64 swap.

### Super Meat Boy after the fix

opengl32 now loads and the game runs its own code:

```
002c:err:wow:wow64_NtMapViewOfSection Playport: i386 image C:\windows\system32\wined3d.dll at 79b80000
002c:err:wow:wow64_NtMapViewOfSection Playport: i386 image C:\windows\system32\opengl32.dll at 79a40000
[unixlib] module 0x70b2390000 (opengl32.dll) WoW64 -> 0x1644e2638 (GL-absent table)
[exc-disp]   OutputDebugStringA: "Loading file: UserData/TommunismEngine.log
[exc-disp]   OutputDebugStringA: "Loading file: UserData/SMBLog.log
[exc-disp]   OutputDebugStringA: "Creating Window
002c:err:wow:window_unaudited Playport: i386 win32u system call 15d0 (args 00000070398DF5CC: 00010034 ffffffff 00000400 00000001); its thunk is not audited for the guest window, stopping
002c:err:process:NtTerminateProcess NtTerminateProcess(handle=0xffffffffffffffff, exit_code=0xc00000bb) syscalls=0 unix_calls=637
```

No `err:opengl` and no `loader_init` failure. The next blocker is in `wow64win`: win32u
call `0x15d0` is `NtUserThunkedMenuItemInfo` (`dlls/win32u/win32syscalls.h`). Its WoW64 thunk is
not on the audited list for an i386 child in the guest window, so `window_unaudited` stops the
process with `STATUS_NOT_SUPPORTED`. The arguments (menu `0x10034`, position `-1`, flags
`0x400` = `MF_BYPOSITION`, method 1 = `NtUserInsertMenuItem`) are a menu item insert
(`InsertMenuItem`, appending) while the game creates its window. The screenshot shows Playport's Home screen with "Super Meat Boy stopped
unexpectedly. It exited with code 0xC00000BB." The game stays Broken. This blocker is not
fixed here.
