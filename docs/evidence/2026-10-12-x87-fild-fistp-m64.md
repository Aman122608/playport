the conservative option was taken at each choice below. **IPA:** `Playport-26.5-3e81f622.ipa`

## The bug

[2026-10-12-mkke-import-x87](2026-10-12-mkke-import-x87.md): Mortal Kombat Komplete Edition
(i386, MSVC) pops a lock-free list at `MKKE.exe` `0x7145bd`. It loads the 64-bit {pointer, tag}
head with `fild qword [ecx]; fistp qword [ebp-0x20]`, 32-bit MSVC's atomic 64-bit load. Under
`X87ReducedPrecision=1` (decision [0048](../decisions/0048-x87-reduced-precision-global.md)) FEX
holds the x87 stack in doubles. With the tag `0x84280002` in the high half, the integer is near
2^63, so the double keeps the pointer only to 1,024 bytes, and the game crashes with `c0000005`
about 69 s in. 80-bit x87 ran clean.

Upstream FEX has no fix: none of the 23 FEX-Emu/FEX `main` commits after the `fex` pin touches
the x87 dispatcher or the x87 stack pass, and no commit in FEX's history names this case.

## The change: `patches/fex` 0025

FEX's x87 stack pass (`x87StackOptimizationPass.cpp`) already tracks, for each value it holds on
the stack within a block, the memory value it was loaded from. It uses that so that `fld m64; fst
m64` copies the bits. 0025 adds the same tracking for the integer of a `fild m64` in reduced
precision:

- `FILDF64` for a 64-bit source emits `PushStackFromInt64(double, integer)`, a new x87 IR op. The
  pass pushes the double as before and keeps the loaded integer beside it.
- `FISTF64` for a 64-bit destination (`fistp`, `fist`, `fisttp`) passes its converted integer
  through `ReadStackInt64`, a new x87 IR op. The pass resolves it to the kept integer when the top
  of the stack is that unchanged value, and to the converted double otherwise.
- The integer stays with the value when FXCH, `fld st(i)` or `fst st(i)` move or copy it. Any
  operation that computes a new value drops it. So does the pass's slow path, and so does the
  next block, because each block starts again.

An integer-valued x87 value converts to an integer exactly under every rounding mode, and an int64
fits in the 80-bit format. So the result is what 80-bit x87 stores; flags and tags are unchanged.
When no `fist m64` uses the kept integer, its GPR-to-FPR move is dead and dead-code elimination
removes it. A `fild` alone compiles to the same code as before. The pair compiles to a load, an
`fmov` and a store, with no conversions. A FEX asm test,
`unittests/ASM/X87_F64/FILD_FISTP_I64_Exact_F64.asm`, covers the four exact forms and the rounded
changed value. It was not run: FEX's test harness needs an ARM64 Linux host, and this workstation
has none.

## What stays open

- The exact path holds only while the `fild` and the `fist` are in one FEX block with nothing
  computing on the value between them. That is MSVC's idiom and the probe's forms. A value moved
  to another block, or spilled through FEX's slow stack path, is a double again. Decision 0048's
  cost for 64-bit integers that are computed on stays.
- The FEX asm test has not been run (no ARM64 Linux host).
- MKKE frame rate in a fight (53 FPS) is not investigated.
