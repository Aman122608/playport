# 2026-10-11: OpenAL from GOG's dependency repository (PLA-182, PLA-183)

**Linear:** [PLA-182](https://linear.app/playportdev/issue/PLA-182),
[PLA-183](https://linear.app/playportdev/issue/PLA-183),
[PLA-24](https://linear.app/playportdev/issue/PLA-24).
**Decision:** [0090](../decisions/0090-gog-redistributables.md).
**Question:** where does `OpenAL32.dll` come from under Proton, and does Baldur's Gate: Enhanced
Edition (GOG 1207666353) start when Playport does the same?
**Result:** neither Wine nor Proton has `OpenAL32.dll`; GOG's build names `"dependencies":
["openAL"]`, which GOG Galaxy and Heroic install by running GOG's `__redist/openAL/oalinst.exe /S`.
Under Proton 10.0 that installer makes a 64-bit and a 32-bit OpenAL device work in a fresh prefix.
Playport now runs the same installer once per prefix from Play; Baldur's Gate EE reaches its main
menu (it exited with `0xc0000135` before).

## Proton (workstation)

Scratch prefix under `$PLAYPORT_BUILD/openal/`, Proton 10.0 `waitforexitandrun`, sway display. A probe
(`alprobe.c`, llvm-mingw, x86-64 and i686) calls `LoadLibrary("OpenAL32.dll")`, `alcOpenDevice(NULL)`,
`alcCreateContext` and `alcMakeContextCurrent`.

- **Builtins:** `find files -iname '*openal*'` in Proton 10.0, Proton 11.0 and Proton - Experimental:
  nothing. The wine pin's `dlls/` has no `openal32` either.
- **Fresh prefix:** the probe exits 2, `OpenAL32.dll` not found (the phone's `0xc0000135`).
- **After `oalinst.exe /S`** (809,496 bytes, md5 `694f54bd227916b89fc3eb1db53f0685`, from GOG's dependency
  store, no sign-in), exit 0: `system32/OpenAL32.dll` (122,904 bytes), `system32/wrap_oal.dll`,
  `syswow64/OpenAL32.dll` (109,080), `syswow64/wrap_oal.dll`. The probe, both architectures:
  `OpenAL32.dll: C:\windows\system32\OpenAL32.dll`, device `Generic Software`, context made current.
- **How a GOG game gets it under Proton:** Heroic's GOG setup (`src/backend/storeManagers/gog/setup.ts`)
  takes the build manifest's `dependencies`, finds each in GOG's redistributable manifest, skips one
  with no `executable.path`, and runs the rest in the prefix with the manifest's arguments.
  GOG's repository (`content-system.gog.com/dependencies/repository?generation=2`) lists 68 entries on
  2026-10-11, `openAL` as `__redist/openAL/oalinst.exe /S`, "Open AL (2.0.7.0)".
- **Baldur's Gate EE's build** 59804716415913588 (2.7.3.0-s): `dependencies: ["openAL"]`,
  `scriptInterpreter: true`. Its own depot also holds `oalinst.exe` at the game's root, the same size
  as GOG's. The game itself was not run under Proton: its files need a GOG sign-in (3.35 GB), and the
  phone answered the question directly.

## DiRT 3 (Steam), not run

DiRT 3 ships `_CommonRedist/OpenAL/2.0.7.0/oalinst.exe` with an install script whose one entry runs it
with `/s` (HasRunKey `HKLM\Software\Valve\Steam\Apps\CommonRedist\OpenAL\2.0.7.0`). PlayportKit's
`SteamPrerequisites.add` makes it a prerequisite with that id (`…\OpenAL\2.0.7.0|2.0.7.0`) and writes
the HasRunKey after exit 0 or 3010 (`SteamInstallScriptTests.testAGamesOwnOpenALInstallerBecomesAPrerequisiteWritingItsHasRunKey`,
decision 0081). It is the same Creative 2.0.7.0 installer that ran on the phone above. Not played: the
title is a 15 GB local import later in the queue.

## Not covered

- GOG's install script (`goggame-<id>.script`, run by `__redist/ISI/scriptinterpreter.exe` when the
  build says `scriptInterpreter`) is not run; Baldur's Gate EE did not need it to reach its menu.
- `.msi` redistributables (XNA) are left out; the repository's signature fields are not checked.
